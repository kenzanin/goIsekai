* [Chapter order newest-first (ABI)](concept/chapter-order-newest-first-abi.md) - Two plugins reversed the site's newest-first chapter fragment, so a library manga read 74,73,72… and the same series live read 1,2,3…; the ABI is newest-first, comizy's "progress is keyed off chapter_num" was false, and split labels "Chapter 12-2" need folding to 12.2
* [Prod file split refactor](concept/prod-file-split-refactor.md) - Every prod file over 200 lines that held many functions is now split (17 files, 32 new ones); the rule for when to leave a file alone, the two traps when cutting Go blocks by hand, and the deadcode/staticcheck results
* [Native .so plugins build with zig c++](concept/native-zig-build.md) - New tools/build-native.sh builds every native plugin with zig c++ (g++ fallback): static libc++ means libc.so.6 only, at ~2x the size; the per-plugin -fvisibility=hidden flag is a contract, not a global
* [Static musl .so](concept/static-musl-so.md) - A shared object can be fully self-contained: zig c++ against the host's PIC musl libc.a gives a .so with zero DT_NEEDED entries, so the host needs no libc at all; plus the three traps (--version-script and -Bsymbolic both segfault, -I/usr/include breaks libc++)
* [Native 1manga plugin](concept/native-1manga-plugin.md) - 1manga now runs as a native .so (the Lua original stays in the archive as the reference); byte-identical to the Lua build on all four ABI calls, and the trap that broke it: RapidJSON writes {"index":0.0} where Go wants an integer
* [released_at backfill gap](concept/released-at-backfill-gap.md) - An empty released_at meant "synced before the column existed", not "the plugin does not know the date": the 20 Oct migration added chapters.released_at but never rewrote the old rows, and re-syncing fills them in place
* [atsumaru released_at epoch-millis](concept/atsumaru-released-at-epoch-millis.md) - atsumaru returned zero time 0001-01-01T00:00:00Z for every chapter because the allChapters API's createdAt (epoch millis) was never read; strconv.FormatInt not itoa (wasm32 int overflows 13-digit millis), and a stale plugin_cache made the rebuilt wasm look like it did not take until cleared
* [MangaDex API title= vs website search (word-part fallback)](concept/mangadex-api-title-phrase-vs-website-search.md) - MangaDex API /manga?title= uses exact-ish phrase matching that returns 0 for multi-word phrases (e.g. "Isekai Shoukansareta kedo") while mangadex.org/search shows matches; Odin wasm search_impl now falls back to shorter title prefixes
* [Stale chapter rows prune](concept/stale-chapter-rows-prune.md) - Sync upserted but never pruned, so 196 rows a plugin re-issued stayed forever; the prune deletes a row only when its replacement was in the same answer, and two of my earlier duplicate/orphan counts were measurement artifacts (296 stale rows, not 10,790)
* [MangaBuddy returned zero chapter pages](concept/mangabuddy-empty-chapter-pages.md) - Two defects: the plugin pinned the old CDN host in its page matcher, and the host then cached the empty answer and served it back, so the chapter could not recover even after the plugin was fixed
* [Plugin reads its own facts from plugin.json](concept/plugin-json-params.md) - A `params` object in plugin.json holds the values a plugin asks for with `host.plugin.param(name)`; the host injects them because the sandboxes cannot read files, and 32 Lua plugins moved their site facts out of the source
* [BatCave and Manga-Bay plugins solve a custom DLE proof-of-work guard over plain HTTP](concept/batcave-mangabay-dle-plugins.md) - The anti-bot guard is DLE's own 404 challenge, not Cloudflare, so `sha256(token:nonce)` + `POST /_v` beats it without a browser; plus the three traps that looked like parser bugs — a slash in the manga id breaks the fixed-segment `/view/manga` route, the poster `<img>` is sometimes wrapped in an `<a>` so `cover_url` came back empty for a subset of titles, and komacdn.com 403s on every Referer but the site URL *with* its trailing slash
* [Wails desktop client + tray wiring](concept/wails-desktop-client-and-tray.md) - cmd/goisekai-wails is a thin Wails v2 webview wrapper around the running server UI (Qt6 left broken on purpose); mandatory build tags desktop production webkit2_41 + CGO, WebKitGTK quirks (AVIF decode = scroll lag, fixed by the JPEG display transcode at /image; native strip scroll; dark select dropdowns; server-rendered log lane cards), tray client_wails config + status emoji, library 5x5 grid with adaptive covers
* [Library view URL is the source of truth](concept/library-view-url-is-source-of-truth.md) - the stuck-filter bug: gsk:library-view localStorage auto-restore made All/New/In-progress chips bounce back to the last filter; URL-only rule, the New status chip (?status=new -> HasNew), and the jscpd-driven history/updates row merge into partials/manga_list_row
* [1manga: pages field is plaintext JSON, not enc:v1](concept/1manga-plaintext-pages-field.md) - the API now answers chapter.pages as {"p":"<prefix>/","i":["1a.jpg",...]}; the plugin only recognised the encrypted enc:v1 blob, so letter-suffixed pages fell through to a numeric CDN probe that 404'd and the reader rendered an empty chapter with no error; both shapes are now parsed and the probe fails loudly instead of emitting a silent empty list
* [1manga: two stacked GraphQL syntax bugs](concept/1manga-two-stacked-graphql-bugs.md) - search silently returned 0 results because two bugs masked each other: the MangaHub source id was emitted as a quoted string (`x: "mn03"`) where the API wants a `MangaSource` enum value, and the search query closed with three braces instead of two; the third failure mode was a 3.4 MB std-Go build OOMing the wasm runtime — always build via the plugin Makefile (TinyGo, 1.2 MB)
* [Recurring plugin failure patterns](concept/plugin-failure-patterns.md) - Catalog of the six plugin failure modes that resurface across sessions (regex.find_all row shape, released_at zero-time, Lua/RE2 regex, stale plugin_cache, toolchain drift, sandbox decodeString), why each is silent, and the fix
